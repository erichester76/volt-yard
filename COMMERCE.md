# Commerce MVP setup

1. Apply all migrations in timestamp order, including `20261003000000_security_hardening.sql`.
2. Add `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET` to the deployment environment. The two Stripe keys are server-only. Set `NEXT_PUBLIC_APP_URL` to the canonical HTTPS custom-domain origin; Vercel production otherwise derives the deployment origin from `VERCEL_URL`.
3. In Stripe, register `https://YOUR_DOMAIN/api/stripe/webhook` for `checkout.session.completed` and `checkout.session.async_payment_succeeded`, then use its signing secret for `STRIPE_WEBHOOK_SECRET`.
4. For local webhook testing, run `stripe listen --forward-to localhost:3000/api/stripe/webhook` and use the printed signing secret.

Checkout requires a caller-provided `Idempotency-Key` (16-128 URL-safe characters), and creates pricing snapshots plus service requests in one transaction. Stripe webhook events are durably deduplicated and return a retryable 500 when fulfillment fails. Catalog pricing and the pre-negotiated installer payout are loaded server-side from Supabase. The customer pays the retail service price; the order, request, and installer job snapshot the retail amount, payout, and Volt Yard margin. A verified webhook marks the order paid, converts its cart, then offers each request to published compatible shops. `accept_installer_job` is the only client-callable claim path; it verifies an active approved partner, locks the job, records the versioned agreement, and records a pending payout obligation. Payouts are intentionally not sent through Stripe Connect. After an external/manual payout, an admin calls `record_installer_job_payout(job_id, payout_reference)` to record its reference and paid status without initiating a transfer.
